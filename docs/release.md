# Release

This repo publishes two independently versioned artifacts, each driven by its own tag
format.

## The v4 proxy — image + chart (`.github/workflows/release.yml`)

Triggered by a **`v`-prefixed** semver tag (`v*.*.*`) or manual dispatch. It:

1. Builds and pushes the proxy image for **linux/amd64 + linux/arm64** to
   `ghcr.io/<owner>/nutanix-v4-proxy` (tag = the version without the `v`, plus `latest`),
   from `quickstart/middleware/Dockerfile`.
2. Packages `charts/nutanix-v4-proxy` (chart + app version = the resolved version) and
   pushes it to `oci://ghcr.io/<owner>/charts`, then attaches the `.tgz` to the GitHub
   Release.

```console
$ git tag v0.6.0 && git push origin v0.6.0
```

Keep the chart's `Chart.yaml` `version`/`appVersion` in step with the tag; `appVersion`
is the `nutanix_v4_proxy.py` version.

## The VirtualMachine blueprint chart (`.github/workflows/release-chart.yaml`)

Triggered by a **plain-semver** tag (`[0-9]+.[0-9]+.[0-9]+`, no `v`) or manual dispatch.
It `helm lint`s `blueprints/nutanix-virtualmachine`, **verifies the tag matches the
chart's `Chart.yaml` version**, packages it, and pushes to
`oci://ghcr.io/<owner>/charts` (retrying on GHCR first-push flakiness). That published
artifact is what the blueprint's `CompositionDefinition` (`spec.chart.url`) points at.

```console
$ git tag 0.3.0 && git push origin 0.3.0
```

Because the tag format differs (`v0.6.0` for the proxy, `0.3.0` for the blueprint), the
two release workflows do not collide.

## After publishing the blueprint chart

Bump `blueprints/nutanix-virtualmachine/compositiondefinition.yaml`'s
`spec.chart.version` to the published version on `main` — it must point at a version that
exists in the registry. The composition's generated apiVersion follows the chart version
(`0.3.0` → `composition.krateo.io/v0-3-0`), so bumping the chart's major/minor/patch
changes the composition GVK (see [api](./api.md)).

## PR-time and push checks

- **`ci.yml`** — on changes to `quickstart/middleware/**` or `charts/nutanix-v4-proxy/**`:
  builds the proxy image (no push), smoke-tests `/healthz`, `helm lint`s and renders the
  proxy chart, and asserts the chart **refuses** to render without `config.pcBase`.
- **`security.yml`** — the shared `krateo-platformops/.github` security scan on every push
  and PR to `main`.
- **`lint.yaml`** — runs the shared docs-standard linter (`lint-docs`) so this bundle
  stays conformant.

## The generated RestDefinitions

`generated/` is regenerated by `scripts/generate_restdefinitions.py` from the official
specs in `oas/_official/` (the script clears the directory first). It is not tied to a
release tag; regenerate and commit when the upstream Nutanix v4 specs change, keeping the
hand-maintained `generated/README.md` / `generated/ANALYSIS.md`.
