# Generated Krateo RestDefinitions — Nutanix v4 (1:1)

Auto-generated, **1:1 Krateo `RestDefinition`s for the full Nutanix Prism Central
v4 API surface** — one resource → one RestDefinition (→ one CRD + controller).

- **Source specs:** official Nutanix v4 OpenAPI specs in [`../oas/_official/`](../oas/_official) (19 namespaces, from `https://developers.nutanix.com/api/v1/namespaces/{ns}/versions/{ver}/yaml`).
- **Generator:** [`../scripts/generate_restdefinitions.py`](../scripts/generate_restdefinitions.py)
- **Inventory:** [`ANALYSIS.md`](ANALYSIS.md) — every resource, verbs, sync/async, slice size.
- **189 resources** across all 19 namespaces.

> ⚠️ This directory is regenerated by the script (which clears it first). This README
> is hand-maintained — keep a copy if you re-run the generator.

## Layout
```
generated/
  00-namespace.yaml          kustomization.yaml          ANALYSIS.md   README.md
  <namespace>/
    oas/<kind>.yaml                          # trimmed OAS slice (this resource only)
    restdefinitions/<kind>.restdefinition.yaml
```

## How each resource is produced
1. **Trimmed OAS slice** — only that resource's paths plus the **transitive `$ref`
   closure** of the schemas they touch → a self-contained, valid OpenAPI 3.0.1 doc,
   **< 1 MB** so it fits a ConfigMap (full vmm spec alone is 2.3 MB).
   The slice is **sanitized**: `default`/`example` values and Nutanix `$`-prefixed
   reserved fields (`$reserved`, `$objectType`, `$fv`) are stripped — they break
   Kubernetes/oasgen CRD generation (float `default` on an `int32`; invalid Go ids).
2. **RestDefinition** mapping CRUD → endpoints (`findby`=GET coll, `create`=POST coll,
   `get`/`update`/`delete`=GET/PUT/DELETE coll/{id}). `identifiers` prefer `name`;
   `{id}` path param ← `status.extId`; OData query params (`$filter`/`$page`/`$limit`/…)
   are listed in `excludedSpecFields` (not desired-state).

## Apply
Prereq: a cluster with **Krateo + `oasgen-provider`** (`restdefinitions.ogen.krateo.io`).
```bash
kubectl apply -k generated/                 # namespace + 189 ConfigMaps + 189 RestDefinitions
kubectl get restdefinitions -n nutanix-system            # READY -> True
kubectl get crd | grep nutanix.krateo.io                 # resource + Configuration CRDs
```
> Applying all 189 spins up **189 controller Deployments** — heavy for a small/KIND
> cluster (a default node caps at ~110 pods). Apply a subset there.

## Validated on real infrastructure (`kind-nova-kog`, oasgen-provider live)
- **186 / 189** RestDefinitions reconcile cleanly (`Synced=True`) — oasgen parses the
  slice and generates the resource CRD + `*Configuration` CRD + controller.
- Full schema fidelity (e.g. `Vm`: `name`, `numSockets`, `memorySizeBytes`, `disks[]`,
  `nics[]`, `cluster`, `bootConfig`…), query params correctly excluded.
- At full scale, controllers reach `Ready` as node capacity allows (the unready ones
  on KIND were blocked by the **110-pod cap**, not by any defect).

## Known limitations
- **3 resources fail oasgen's CRD codegen** (`clustermgmt/clusterprofile`,
  `clustermgmt/trap`, `vmm/version`): oasgen builds Go types from the schema and chokes
  on Nutanix's `Version` type / redacted-enum construct (`unknown type Version`). This
  is an **oasgen/crdgen limitation**, not the slice content — needs an upstream fix or
  a per-resource schema patch.
- **`identifiers` are immutable** post-generation — change them only via delete+recreate.
- **Most v4 write ops are async** (`202` + TaskReference; `PUT`/`DELETE` need `If-Match`
  ETag + `Ntnx-Request-Id`). Real create/update/delete round-trips need task-polling +
  ETag replay (a wrapper or controller support). See `ANALYSIS.md` for which are async.
